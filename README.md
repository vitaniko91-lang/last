# LAST

Вымышленный DTC-бренд ухода за кожей и обувью. Портфолио-кейс: витрина с живым
конфигуратором, построенная на замере четырёх реальных магазинов категории.

- **Сайт:** см. деплой
- **Figma (публичный файл):** https://www.figma.com/design/ztM2VHMovlutEykLNGPLVq
- **Аудит категории:** `docs/portfolio/last/audit/category-audit.md`
- **Дизайн-система:** `docs/portfolio/last/design-system/`
- **Экраны:** `docs/portfolio/last/screens.md`

## Что здесь есть и чего нет

Пять страниц: главная, каталог, карточка товара, конфигуратор, корзина, плюс
страница кейса.

**Чекаут и аккаунт с графиком пополнения в коде не делаются.** Они собраны
целиком в Figma, и это решение, а не недоделка: обещать целый магазин и не
сделать — хуже, чем очертить границу вслух. На экране корзины и на странице
кейса это сказано прямо.

## Движок

`src/kit/` — вся логика подбора, без React и без DOM:

| Модуль | Что решает |
|---|---|
| `catalogue.ts` | девять позиций: роль, расход, оттенки, цена |
| `rules.ts` | матрица «материал × задача» и шесть объяснённых конфликтов |
| `resolve.ts` | ответы → набор: дедупликация, каталожный порядок, замены |
| `schedule.ts` | срок по позиции, которая кончится первой |
| `identify.ts` | определение материала по признакам, которые видит владелец |

Ни одно число на страницах не написано в вёрстке. «2 месяца», «3 790 ₽» и текст
конфликта приходят отсюда.

## Токены

`docs/portfolio/last/design-system/tokens.json` — единственный источник истины.
`npm run tokens` компилирует его в `src/styles/tokens.css`. Правится JSON, не CSS.

## Команды

```
npm run dev             # разработка
npm test                # 143 теста
npm run typecheck       # tsc --noEmit
npm run build           # типы + продакшн-сборка
npm run tokens          # пересобрать tokens.css из tokens.json
npm run qa:responsive   # замер переполнения и зон нажатия на трёх ширинах
```
